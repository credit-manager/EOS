## 1. Standard Response Wrapper

### 1.1 Success Response

```json
{
  "status": "success",
  "data": { ... },
  "meta": {
    "request_id": "uuid",
    "timestamp": "2026-08-24T12:00:00Z",
    "entity_code": "account",
    "tenant_capability": "SCOPED",
    "effective_tenant": "tenant-123"
  }
}
```

### 1.2 Error Response

```json
{
  "status": "error",
  "error": {
    "code": "ERROR_CODE",
    "message": "Arabic message",
    "message_en": "English message",
    "details": [...]
  },
  "meta": {
    "request_id": "uuid",
    "timestamp": "2026-08-24T12:00:00Z"
  }
}
```

### 1.3 Meta Fields

| Field | Type | Always Present | Description |
|-------|------|----------------|-------------|
| `request_id` | uuid | Yes | Correlation ID for debugging |
| `timestamp` | ISO8601 | Yes | Response generation time |
| `entity_code` | string | Yes | Entity being operated on |
| `tenant_capability` | enum | Yes | `SCOPED` or `NONE` |
| `effective_tenant` | string | SCOPED only | Tenant ID from JWT |
| `pagination` | object | LIST only | Pagination info |

## 4. Request Rules

### 4.1 System-Managed Fields (Never in Payload)

| Field | Behavior |
|-------|----------|
| `id` | Auto-generated UUID |
| `tenant_id` | Set from JWT for SCOPED |
| `created_at` | PostgreSQL DEFAULT |
| `updated_at` | Not yet supported |
| `deleted_at` | Not yet supported |

### 4.2 Payload Rules

| Rule | Description |
|------|-------------|
| Unknown fields | Silently ignored (no error) |
| Empty payload `{}` | POST: rejected (at least 1 field) |
| Empty payload `{}` | PUT: rejected (no columns to update) |
| `id` in payload | Silently ignored |
| `tenant_id` in payload | SCOPED: silently replaced with JWT tenant |
| `tenant_id` in payload | NONE: silently ignored |

## 5. Pagination Contract

### 5.1 Response Format

```json
{
  "pagination": {
    "total": 150,
    "limit": 100,
    "offset": 0,
    "has_more": true
  }
}
```

### 5.2 Fields

| Field | Type | Description |
|-------|------|-------------|
| `total` | integer | Total records matching query |
| `limit` | integer | Records per page |
| `offset` | integer | Records skipped |
| `has_more` | boolean | `true` if more records exist |

### 5.3 Calculation

```
has_more = (offset + limit) < total
```

### 5.4 Performance Note

`total` requires a COUNT query. For large tables, this may be slow.
Future optimization: cursor-based pagination (no total count).

## 6. Audit Integration

### 6.1 Audit Log Entry (per operation)

| Field | CREATE | UPDATE | DELETE |
|-------|--------|--------|--------|
| `action` | `"create"` | `"update"` | `"delete"` |
| `old_values` | null | null (deferred) | record snapshot |
| `new_values` | full record | changed fields | null |

### 6.2 Known Limitation

UPDATE `old_values` is not captured due to transaction interaction with audit INSERT. This is a deferred finding.
