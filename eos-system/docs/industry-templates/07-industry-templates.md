## 1. المقدمة والمبادئ العامة

### 1.1 فلسفة القوالب الصناعية

| البند | التفاصيل |
|--------|---------|
| **المبدأ الأساسي** | كل قالب صناعي هو طبقة تخصيص (Customization Layer) مبنية فوق الوحدات الأساسية للنظام |
| **البنية** | Core Modules + Industry Template = Solution Complete |
| **التعددية** | يمكن تفعيل أكثر من قالب صناعي في نفس الـ tenant إذا كان النشاط متنوعاً |
| **العزل** | بيانات كل tenant معزولة تماماً (Data Isolation) عبر database schema أو row-level security |
| **الترقية** | الترقات الرئيسية (Major Upgrades) لا تؤثر على القوالب المخصصة |

### 1.2 الوحدات الأساسية - Core Modules

| الوحدة | الكود | الوصف |
|--------|------|-------|
| المحاسبة | ACCT | Core Accounting, GL, AP, AR |
| المخزون | INV | Inventory Management, Warehouses |
| نقطة البيع | POS | Point of Sale |
| الموارد البشرية | HR | Human Resources, Payroll |
| المبيعات | SALES | Sales Orders, Quotations |
| إدارة المشاريع | PROJECT | Project Management |
| سلسلة التوريد | SCM | Supply Chain Management |
| خدمة العملاء | CS | Customer Service |
| التصنيع | MFG | Manufacturing |
| إدارة علاقات العملاء | CRM | Customer Relationship Management |

### 1.3 هيكل القالب الصناعي - Industry Template Structure

كل قالب صناعي يحتوي على:

`
Industry Template/
├── manifest.json          # تكوين القالب الأساسي
├── modules/               # الوحدات المخصصة
│   ├── custom_fields.json
│   ├── custom_screens.json
│   ├── custom_workflows.json
│   └── custom_reports.json
├── roles/                 # الأدوار المخصصة
│   └── roles.json
├── dashboards/            # لوحات المتابعة
│   └── dashboards.json
├── integrations/          # التكاملات الخارجية
│   └── integrations.json
├── settings/              # الإعدادات المخصصة
│   └── settings.json
└── seed_data/             # البيانات الأولية
    └── seed.json
`

### 1.4 قواعد تسمية الحقول المخصصة

| القاعدة | المثال |
|---------|--------|
| prefix بحرف lowercase من الوحدة | ph_drug_name, est_table_no |
| snake_case | ph_scientific_name |
| لا تبدأ بـ underscore | drug_name (صحيح) / _drug_name (خطأ) |
| suffix للتواريخ | _at للـ timestamps, _date للتواريخ |
| suffix للأرقام | _no for numbers, _id for IDs |

### 2.4 سير العمل - Workflows

#### 2.4.1 سير عمل استلام الدواء - Drug Receiving Workflow

`
استلام الشحنة
    |
مسح الباركود لكل صنف
    |
التحقق من رقم التشغيلة وتاريخ الانتهاء
    |
[تاريخ الانتهاء < 6 اشهر؟] ---نعم---> رفض الشحنة
    | لا
التحقق من المطابقة مع طلب الشراء
    |
ادخال الكمية في المخزون
    |
تحديث مخزون الصيدلية
    |
انشاء قيد محاسبي (Debit: Inventory, Credit: AP)
    |
اشعار الصيدلي بالاستلام
`

#### 2.4.2 سير عمل بيع الدواء - Drug Selling Workflow

`
مسح الباركود / بحث الدواء
    |
التحقق من المخزون
    |
[المخزون = 0؟] ---نعم---> اقتراح بديل
    | لا
[الدواء خاضع للرقابة؟] ---نعم---> طلب بيانات المستلم
    | لا

    | لا
[الدفع بالتأمين؟] ---نعم---> حساب المشاركة الذاتية
    | لا
اتمام البيع
    |
تحديث المخزون
    |
انشاء قيد محاسبي
    |
طباعة الايصال
`

#### 2.4.3 سير عمل تجديد المخزون - Restocking Workflow
