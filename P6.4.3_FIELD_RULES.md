## 1. Field Type Validation Matrix

### 1.1 Type → PostgreSQL Mapping

| Field Type | PostgreSQL Type | Accepts | Rejects |
|------------|-----------------|---------|---------|
| `string` | VARCHAR(n) | `"hello"`, `""` | `null` (if required), > maxLength |
| `text` | TEXT | Any text | `null` (if required), > maxLength |
| `integer` | INTEGER | `42`, `-5`, `0` | `"abc"`, `3.14`, > max, < min |
| `decimal` | DECIMAL(p,s) | `3.14`, `"10.50"` | `"abc"`, > max, < min, wrong precision |
| `boolean` | BOOLEAN | `true`, `false`, `0`, `1` | `"abc"`, `"true"` (string) |
| `date` | DATE | `"2026-08-24"` | `"24-08-2026"`, `"abc"`, invalid date |
| `datetime` | TIMESTAMP | `"2026-08-24T12:00:00Z"` | Invalid ISO 8601 |
| `json` | JSONB | `{"key": "value"}`, `[1,2,3]` | `"string"`, invalid JSON |
| `enum` | VARCHAR | One of `enum_values[]` | Value not in enum_values |

### 1.2 Validation Rules by Type

#### string
```yaml
type: string
postgresql: VARCHAR(n)
validation:
  - type: must be string or null
  - maxLength: from ui_config.maxLength (default: 255)
  - pattern: none (any characters allowed)
  - whitespace: trimmed
  - empty_string: allowed (if not required)
errors:
  INVALID_TYPE: "يجب أن يكون نصاً"
  TOO_LONG: "يجب أن لا يتجاوز {maxLength} حرفاً"
```

#### text
```yaml
type: text
postgresql: TEXT
validation:
  - type: must be string or null
  - maxLength: from ui_config.maxLength (default: 10000)
  - whitespace: preserved
  - empty_string: allowed (if not required)
errors:
  INVALID_TYPE: "يجب أن يكون نصاً"
  TOO_LONG: "يجب أن لا يتجاوز {maxLength} حرفاً"
```

#### integer
```yaml
type: integer
postgresql: INTEGER
validation:
  - type: must be integer or null
  - min: from ui_config.min (default: -2147483648)
  - max: from ui_config.max (default: 2147483647)
  - decimal: rejected (3.14 → error)
  - string_integer: rejected ("42" → error)
errors:
  INVALID_TYPE: "يجب أن يكون عدداً صحيحاً"
  OUT_OF_RANGE: "يجب أن يكون بين {min} و {max}"
```

#### decimal
```yaml
type: decimal
postgresql: DECIMAL(precision, scale)
validation:
  - type: must be number or string number or null
  - min: from ui_config.min
  - max: from ui_config.max
  - precision: from ui_config.precision (default: 2)
  - string_decimal: accepted ("10.50" → 10.50)
  - rounding: round to precision
errors:
  INVALID_TYPE: "يجب أن يكون عدداً"
  OUT_OF_RANGE: "يجب أن يكون بين {min} و {max}"
  PRECISION_ERROR: "يجب أن يحتوي على {precision} خانات عشرية"
```

#### boolean
```yaml
type: boolean
postgresql: BOOLEAN
validation:
  - type: must be boolean, 0, or 1
  - true/false: accepted
  - 0/1: accepted
  - "true"/"false" (string): rejected
  - truthy/falsy: rejected
errors:
  INVALID_TYPE: "يجب أن يكون منطقياً (true/false)"
```

#### date
```yaml
type: date
postgresql: DATE
validation:
  - type: must be string in ISO 8601 format
  - format: YYYY-MM-DD
  - example: "2026-08-24"
  - invalid_dates: rejected (2026-02-30, 2026-13-01)
errors:
  INVALID_TYPE: "يجب أن يكون تاريخاً بصيغة YYYY-MM-DD"
  INVALID_DATE: "التاريخ غير صحيح"
```

#### datetime
```yaml
type: datetime
postgresql: TIMESTAMP
validation:
  - type: must be string in ISO 8601 format
  - format: YYYY-MM-DDTHH:MM:SSZ or YYYY-MM-DDTHH:MM:SS+HH:MM
  - example: "2026-08-24T12:00:00Z"
  - timezone: optional (UTC assumed if not provided)
errors:
  INVALID_TYPE: "يجب أن يكون تاريخاً ووقتاً بصيغة ISO 8601"
  INVALID_DATETIME: "التاريخ والوقت غير صحيحين"
```

#### json
```yaml
type: json
postgresql: JSONB
validation:
  - type: must be valid JSON
  - objects: accepted
  - arrays: accepted
  - strings: rejected (not valid JSON object)
  - null: accepted (if not required)
errors:
  INVALID_JSON: "يجب أن يكون كائناً JSON صالحاً"
```

#### enum
```yaml
type: enum
postgresql: VARCHAR
validation:
  - type: must be string
  - value: must be in enum_values[]
  - case_sensitive: yes
  - enum_values: from field definition
errors:
  INVALID_ENUM: "يجب أن يكون أحد القيم: {enum_values}"
```

## 2. Nullability Rules

### 2.1 Source of Truth

| Source | Priority | Description |
|--------|----------|-------------|
| PostgreSQL NOT NULL | 1 (highest) | Database constraint |
| `is_required` in DBPField | 2 | Application-level required |
| Payload presence | 3 | Field present in request? |
| Value check | 4 | Value is null/empty? |

### 2.2 Nullability Matrix

| PostgreSQL NOT NULL | is_required | Payload | Value | Result |
|---------------------|-------------|---------|-------|--------|
| YES | — | Present | Not null | ✅ OK |
| YES | — | Present | null | ❌ NOT_NULL_VIOLATION |
| YES | — | Missing | — | ❌ NOT_NULL_VIOLATION |
| NO | YES | Present | Not null | ✅ OK |
| NO | YES | Present | null | ❌ VALIDATION_ERROR |
| NO | YES | Missing | — | ❌ VALIDATION_ERROR |
| NO | NO | Present | Not null | ✅ OK |
| NO | NO | Present | null | ✅ OK (stored as null) |
| NO | NO | Missing | — | ✅ OK (stored as null) |

### 2.3 Empty String vs Null

| Value | `is_required` | Result |
|-------|---------------|--------|
| `" "` (whitespace only) | YES | ❌ VALIDATION_ERROR (trimmed to empty) |
| `""` (empty string) | YES | ❌ VALIDATION_ERROR |
| `""` (empty string) | NO | ✅ OK (stored as empty string) |
| `null` | YES | ❌ VALIDATION_ERROR |
| `null` | NO | ✅ OK (stored as null) |

## 3. Type Coercion Rules

### 3.1 What Gets Coerced

| Input | Field Type | Coerced To | Notes |
|-------|------------|------------|-------|
| `"42"` | integer | ❌ Rejected | String not accepted for integer |
| `42` | string | `"42"` | Integer converted to string |
| `"3.14"` | decimal | `3.14` | String decimal accepted |
| `true` | boolean | `true` | Direct |
| `"true"` | boolean | ❌ Rejected | String not accepted |
| `"2026-08-24"` | date | `date(2026,8,24)` | ISO format accepted |
| `1724505600` | datetime | ❌ Rejected | Timestamp not accepted |

### 3.2 Coercion Priority

```
1. Check type matches exactly → accept
2. Check safe coercion rules → coerce or reject
3. All other inputs → reject
```

## 4. Validation Order

```
1. Parse JSON payload
2. For each field in schema:
   a. Check if field exists in payload
      → If missing and required: VALIDATION_ERROR
      → If missing and not required: skip (use default/null)
   b. Check value is not null
      → If null and required: VALIDATION_ERROR
      → If null and not required: skip
   c. Check type matches field_type
      → If wrong type: INVALID_TYPE error
   d. Apply type-specific validation
      → maxLength, min/max, pattern, enum values
   e. Apply NOT NULL constraint check
      → If PostgreSQL NOT NULL and value is null: NOT_NULL_VIOLATION
3. After all fields validated:
   a. Check NOT NULL columns from PostgreSQL
      → If any NOT NULL column missing: NOT_NULL_VIOLATION
   b. Check unique constraints
      → If duplicate: DUPLICATE_RECORD
```

## 6. Special Cases

### 6.1 `id` Field
- **Never validated** — system-managed
- **Never accepted** in payload — silently ignored
- **Always generated** as UUID on INSERT

### 6.2 `tenant_id` Field
- **Never validated** against DBPField schema
- **Never accepted** in payload for SCOPED entities
- **Always set** from JWT token for SCOPED entities
- **Always excluded** from WHERE clause for NONE entities

### 6.3 Unknown Fields
- Fields in payload that don't exist in table → **silently ignored**
- No error thrown for extra fields
- Only valid columns are inserted/updated

### 6.4 Empty Payload
- POST with `{}` → **rejected** (at least one non-system field required)
- PUT with `{}` → **rejected** (no columns to update)
