# P6.4.2 — Canonical Entity Contract

**Status:** DRAFT — Awaiting Approval
**Date:** 2026-08-24
**Decisions:** ALL entities, No inheritance, No computed fields, No field-level RBAC

## 1. Entity Definition

### 1.1 What is an Entity?

An Entity is a **virtual data model** mapped to a real PostgreSQL table.

```
Entity (metadata)  →  PostgreSQL Table (real)
     ↓                      ↓
dbp_entities         actual_table
dbp_fields           actual_columns
```

### 1.2 Entity Properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `code` | string(100) | ✅ | Unique identifier. Lowercase, underscores only. Pattern: `^[a-z][a-z0-9_]*$` |
| `name_en` | string(255) | ✅ | English display name |
| `name_ar` | string(255) | ❌ | Arabic display name |
| `faculty` | string(50) | ✅ | Business domain (e.g., "finance", "hr", "inventory") |
| `table_mapping` | string(100) | ✅ | PostgreSQL table name. Must exist. Pattern: `^[a-z][a-z0-9_]*$` |
| `is_system` | boolean | ✅ | System entities cannot be deleted |
| `tenant_handling` | enum | ✅ | `SCOPED` or `NONE` (derived from table schema) |

### 1.3 Entity Code Rules

```
✅ Valid:   account, bank_account, student_enrollment, item
❌ Invalid: Account, bank-account, bank account, 123item
```

### 1.4 Tenant Capability

Determined **automatically** by PostgreSQL table inspection:

| Table has `tenant_id` column | Capability | Behavior |
|------------------------------|------------|----------|
| Yes | `SCOPED` | All operations filtered by authenticated tenant |
| No | `NONE` | No tenant filtering. Global data. |

**The `dbp_entities.tenant_id` column is NOT used for filtering.**
**Tenant value comes ONLY from JWT token.**

## 2. Field Definition

### 2.1 Field Properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `code` | string(100) | ✅ | Column name in PostgreSQL. Must match actual column. |
| `label_en` | string(255) | ✅ | English label for UI |
| `label_ar` | string(255) | ❌ | Arabic label for UI |
| `field_type` | enum | ✅ | One of the supported types (see 2.2) |
| `is_required` | boolean | ✅ | If true, value cannot be null/empty |
| `ui_config` | JSON | ✅ | UI rendering hints (see 2.3) |
| `enum_values` | JSON | ❌ | Array of allowed values (only for `enum` type) |

### 2.2 Supported Field Types

| Type | PostgreSQL Type | Validation Rules | Default |
|------|-----------------|------------------|---------|
| `string` | VARCHAR | maxLength (from ui_config) | — |
| `text` | TEXT | maxLength (from ui_config) | — |
| `integer` | INTEGER | min, max (from ui_config) | — |
| `decimal` | DECIMAL(p,s) | min, max, precision (from ui_config) | — |
| `boolean` | BOOLEAN | — | — |
| `date` | DATE | format: ISO 8601 (YYYY-MM-DD) | — |
| `datetime` | TIMESTAMP | format: ISO 8601 | — |
| `json` | JSONB | — | — |
| `enum` | VARCHAR | Must be in enum_values[] | — |

### 2.3 ui_config Schema

```json
{
  "order": 1,           // Display order (integer)
  "width": "full",      // "full" | "half" | "third"
  "placeholder": "...", // Placeholder text
  "help_text": "...",   // Help tooltip
  "min": 0,             // For integer/decimal
  "max": 100,           // For integer/decimal
  "maxLength": 255,     // For string/text
  "precision": 2,       // For decimal (decimal places)
  "format": "YYYY-MM-DD" // For date/datetime
}
```

### 2.4 Field Code Rules

```
✅ Valid:   code, first_name, created_at, is_active
❌ Invalid: Code, first-name, first name, 123code
```

## 3. Schema Contract

### 3.1 GET `/api/v1/dynamic/entities/{entity_code}/schema`

**Response: 200 OK**
```json
{
  "status": "success",
  "data": {
    "entity": {
      "id": "uuid",
      "code": "account",
      "name_en": "Account",
      "name_ar": "حساب",
      "faculty": "finance",
      "table_mapping": "accounts",
      "is_system": false,
      "tenant_handling": "SCOPED"
    },
    "fields": [
      {
        "id": "uuid",
        "code": "code",
        "label_en": "Account Code",
        "label_ar": "رمز الحساب",
        "field_type": "string",
        "is_required": true,
        "ui_config": { "order": 1, "maxLength": 50 },
        "enum_values": []
      }
    ]
  },
  "meta": {
    "real_columns": ["id", "tenant_id", "code", "name", "created_at"],
    "not_null_columns": ["id", "tenant_id", "code"],
    "unique_constraints": [["tenant_id", "code"]],
    "tenant_capability": "SCOPED"
  }
}
```

**Error: 404 Not Found**
```json
{
  "status": "error",
  "error": {
    "code": "ENTITY_NOT_FOUND",
    "message": "الكيان 'xyz' غير موجود",
    "message_en": "Entity 'xyz' not found"
  }
}
```

## 4. CRUD Contract

### 4.1 Standard Response Wrapper

All CRUD responses follow this structure:

```json
{
  "status": "success" | "error",
  "data": { ... },           // Response payload (on success)
  "error": { ... },          // Error details (on error)
  "meta": {
    "request_id": "uuid",    // For correlation
    "timestamp": "ISO8601",  // Response timestamp
    "entity_code": "account",
    "tenant_capability": "SCOPED",
    "effective_tenant": "tenant-123"  // Only for SCOPED entities
  }
}
```

### 4.2 POST `/api/v1/dynamic/entities/{entity_code}/records`

**Request:**
```json
{
  "code": "ACC-001",
  "name": "Bank Account",
  "balance": 10000.00
}
```
> Note: `id`, `tenant_id`, `created_at` are NOT sent. They are system-managed.

**Response: 201 Created**
```json
{
  "status": "success",
  "data": {
    "id": "uuid",
    "code": "ACC-001",
    "name": "Bank Account",
    "balance": 10000.00,
    "tenant_id": "tenant-123",
    "created_at": "2026-08-24T12:00:00Z"
  },
  "meta": {
    "request_id": "uuid",
    "timestamp": "2026-08-24T12:00:00Z",
    "entity_code": "account",
    "tenant_capability": "SCOPED",
    "effective_tenant": "tenant-123"
  }
}
```

**Errors:**
| Status | Code | Condition |
|--------|------|-----------|
| 400 | VALIDATION_ERROR | Required field missing, invalid enum value |
| 400 | NOT_NULL_VIOLATION | Field is NOT NULL in PostgreSQL |
| 401 | UNAUTHORIZED | SCOPED entity, no token provided |
| 403 | FORBIDDEN | Missing `dynamic:create` permission |
| 404 | ENTITY_NOT_FOUND | Entity code doesn't exist |
| 409 | DUPLICATE_RECORD | Unique constraint violation |
| 500 | INTERNAL_ERROR | Database error |

## 5. System-Managed Fields

These fields are NEVER sent in request payloads:

| Field | Source | Behavior |
|-------|--------|----------|
| `id` | Auto-generated UUID | Created on INSERT |
| `tenant_id` | From JWT token | Set from authenticated user |
| `created_at` | PostgreSQL DEFAULT | Set on INSERT |
| `updated_at` | — | Not yet supported |
| `deleted_at` | — | Not yet supported (no soft delete) |

## 6. Validation Rules (Priority Order)

```
1. Entity exists?                    → 404 ENTITY_NOT_FOUND
2. Table exists?                     → 400 TABLE_NOT_FOUND
3. Column exists in table?           → Silently ignored (skip unknown columns)
4. Required field present?           → 400 VALIDATION_ERROR
5. Field type valid?                 → 400 VALIDATION_ERROR
6. NOT NULL constraint satisfied?    → 400 NOT_NULL_VIOLATION
7. Unique constraint satisfied?      → 409 DUPLICATE_RECORD
8. RBAC permission check?            → 403 FORBIDDEN
9. Tenant scope check?               → 401 UNAUTHORIZED
```

## 7. Known Limitations (Deferred)

| Limitation | Status | Impact |
|------------|--------|--------|
| UPDATE old_values not captured in audit | Deferred | Audit log missing old state for updates |
| No soft delete | Deferred | No recovery mechanism |
| No optimistic locking | Deferred | Race conditions possible |
| No field-level validation (min/max) | Deferred | Less data integrity |
| No pagination total count accuracy | Deferred | COUNT query performance |
