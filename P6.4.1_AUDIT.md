## 2. What's Missing (Contract Gaps)

### 2.1 Critical Gaps

| Gap | Impact | Priority |
|-----|--------|----------|
| No field type validation | Invalid data can be inserted | HIGH |
| No response data contract | Client can't predict responses | HIGH |
| No error code contract | Client can't programmatically handle errors | HIGH |
| No pagination contract | Can't handle large datasets | HIGH |

### 2.2 Medium Gaps

| Gap | Impact | Priority |
|-----|--------|----------|
| No filtering/sorting | Can't query specific records | MEDIUM |
| No update response | Client doesn't know what changed | MEDIUM |
| No soft delete | No recovery mechanism | MEDIUM |
| No concurrency control | Race conditions possible | MEDIUM |
| Inconsistent response fields | Client must handle variations | MEDIUM |

### 2.3 Minor Gaps

| Gap | Impact | Priority |
|-----|--------|----------|
| No field constraints (min/max/length) | Less data integrity | LOW |
| No metadata_schema usage | Unused JSON column | LOW |
| No entity creation API | Must use SQL directly | LOW |
| No field ordering enforcement | Order may drift | LOW |

## 4. Current Error Format

```json
// 404
{"detail": "الكيان 'xyz' غير موجود"}

// 400
{"detail": "Field: required"}

// 409
{"detail": "code: موجود بالفعل"}

// 500
{"detail": "Connection refused"}
```

### Problems
- No error code (only HTTP status)
- Arabic messages only (no English fallback)
- Raw exception messages in 500 responses (security risk)
- No structured error body
- No request ID for correlation

## 5. Recommendations for P6.4

### Contract Standardization

1. **Standard Response Wrapper**
   ```json
   {
     "status": "success|error",
     "data": {...},
     "meta": { "request_id": "...", "timestamp": "..." }
   }
   ```

2. **Standard Error Response**
   ```json
   {
     "status": "error",
     "error": {
       "code": "ENTITY_NOT_FOUND",
       "message": "الكيان 'xyz' غير موجود",
       "message_en": "Entity 'xyz' not found"
     },
     "meta": { "request_id": "..." }
   }
   ```

3. **Field Type Validation Rules**
   ```
   string:   maxLength
   integer:  min, max
   decimal:  min, max, precision
   date:     format (ISO 8601)
   datetime: format (ISO 8601)
   boolean:  -
   text:     maxLength
   enum:     values[]
   json:     schema (optional)
   ```

4. **Pagination Contract**
   ```json
   {
     "data": [...],
     "pagination": {
       "total": 150,
       "limit": 100,
       "offset": 0,
       "has_more": true
     }
   }
   ```

5. **Mutating Response Contract**
   ```json
   // POST /records
   { "status": "success", "data": { "id": "...", ...record } }
   
   // PUT /records/{id}
   { "status": "success", "data": { "id": "...", ...updated_record } }
   
   // DELETE /records/{id}
   { "status": "success", "data": { "id": "..." } }
   ```
