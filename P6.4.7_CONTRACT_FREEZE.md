## 2. Response Format

### 2.1 Success Response

```json
{
  "status": "success",
  "data": { ... },
  "meta": {
    "request_id": "uuid",
    "timestamp": "2026-08-24T12:00:00Z",
    "entity_code": "account",
    "tenant_capability": "SCOPED",
    "effective_tenant": "tenant-123"
  }
}
```

### 2.2 Error Response

```json
{
  "status": "error",
  "error": {
    "code": "ERROR_CODE",
    "message": "Arabic message",
    "message_en": "English message",
    "details": []
  },
  "meta": {
    "request_id": "uuid",
    "timestamp": "2026-08-24T12:00:00Z"
  }
}
```

### 2.3 Meta Fields

| Field | Type | When Present |
|-------|------|--------------|
| `request_id` | uuid | Always |
| `timestamp` | ISO8601 | Always |
| `entity_code` | string | Always |
| `tenant_capability` | enum | Always (`SCOPED` or `NONE`) |
| `effective_tenant` | string | Only for SCOPED entities |
| `pagination` | object | Only for LIST endpoint |

## 3. Endpoint Contracts

### 3.1 GET `/api/v1/dynamic/entities/{entity_code}/schema`

**Response 200:**
```json
{
  "status": "success",
  "data": {
    "entity": { "id", "code", "name_en", "name_ar", "faculty", "table_mapping", "is_system", "tenant_handling" },
    "fields": [ { "id", "code", "label_en", "label_ar", "field_type", "is_required", "ui_config", "enum_values" } ]
  },
  "meta": {
    "request_id", "timestamp", "entity_code", "tenant_capability", "effective_tenant",
    "real_columns": [...],
    "not_null_columns": [...],
    "unique_constraints": [...]
  }
}
```

### 3.2 GET `/api/v1/dynamic/entities/{entity_code}/records`

**Query Parameters:** `limit` (1-1000, default 100), `offset` (default 0), `sort`, `order` (asc/desc)

**Response 200:**
```json
{
  "status": "success",
  "data": [ { "id", "tenant_id", ...all_columns } ],
  "meta": {
    "request_id", "timestamp", "entity_code", "tenant_capability", "effective_tenant",
    "pagination": { "total", "limit", "offset", "has_more" }
  }
}
```

### 3.3 POST `/api/v1/dynamic/entities/{entity_code}/records`

**Request Body:** `{ "field1": "value1", ... }` (no id, tenant_id, created_at)

**Response 201:**
```json
{
  "status": "success",
  "data": { "id", "tenant_id", "field1", "value1", "created_at" },
  "meta": { "request_id", "timestamp", "entity_code", "tenant_capability", "effective_tenant" }
}
```

### 3.4 PUT `/api/v1/dynamic/entities/{entity_code}/records/{record_id}`

**Request Body:** `{ "field_to_update": "new_value", ... }`

**Response 200:**
```json
{
  "status": "success",
  "data": { "id", "tenant_id", "all_fields_with_updated_values" },
  "meta": { "request_id", "timestamp", "entity_code", "tenant_capability", "effective_tenant" }
}
```

### 3.5 DELETE `/api/v1/dynamic/entities/{entity_code}/records/{record_id}`

**Response 200:**
```json
{
  "status": "success",
  "data": { "id": "deleted_record_id" },
  "meta": { "request_id", "timestamp", "entity_code", "tenant_capability", "effective_tenant" }
}
```

## 4. Error Codes

| Code | HTTP Status | When |
|------|-------------|------|
| `ENTITY_NOT_FOUND` | 404 | Entity code doesn't exist |
| `TABLE_NOT_FOUND` | 400 | Table doesn't exist in PostgreSQL |
| `TABLE_INVALID` | 400 | Table name contains invalid characters |
| `VALIDATION_ERROR` | 400 | Multiple validation errors |
| `REQUIRED` | 400 | Required field missing |
| `INVALID_TYPE` | 400 | Field type doesn't match |
| `TOO_LONG` | 400 | String exceeds maxLength |
| `OUT_OF_RANGE` | 400 | Number outside min/max |
| `INVALID_ENUM` | 400 | Value not in enum_values |
| `INVALID_DATE` | 400 | Invalid date format |
| `NOT_NULL_VIOLATION` | 400 | NOT NULL column missing |
| `NO_VALID_COLUMNS` | 400 | No valid columns in update payload |
| `DUPLICATE_RECORD` | 409 | Unique constraint violation |
| `UNAUTHORIZED` | 401 | No token provided |
| `INVALID_TOKEN` | 401 | Token invalid/expired |
| `FORBIDDEN` | 403 | Missing required permission |
| `RECORD_NOT_FOUND` | 404 | Record doesn't exist |
| `INTERNAL_ERROR` | 500 | Server error |

## 5. Validation Rules

### 5.1 Field Types

| Type | Validates |
|------|-----------|
| `string` | maxLength |
| `text` | maxLength |
| `integer` | min, max, no decimals |
| `decimal` | min, max, precision |
| `boolean` | true/false/0/1 |
| `date` | ISO 8601 YYYY-MM-DD |
| `datetime` | ISO 8601 format |
| `json` | Valid JSON |
| `enum` | Value in enum_values[] |

### 5.2 Nullability Priority

```
1. PostgreSQL NOT NULL (highest)
2. is_required
3. Payload presence
4. Value check
```

### 5.3 System-Managed Fields (Never in Payload)

`id`, `tenant_id` (SCOPED), `created_at`

## 7. Known Limitations (Deferred)

| Limitation | Impact |
|------------|--------|
| UPDATE old_values not captured | Audit log missing old state |
| No soft delete | No recovery |
| No optimistic locking | Race conditions |
| No field-level validation (min/max) | Less data integrity |
| COUNT query performance | May be slow on large tables |
